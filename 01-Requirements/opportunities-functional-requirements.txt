ESPOCRM QA AUTOMATION PROJECT
OPPORTUNITIES MODULE - FUNCTIONAL REQUIREMENTS
Version: v1.0

============================================================
DOCUMENT PURPOSE
============================================================

This document records the functional requirements identified
during exploratory observation of the EspoCRM Opportunities module.

The requirements are based on the observed Opportunities module
page, Create Opportunity form, dropdown values, List/Kanban views,
and stage-specific creation controls.

Application : EspoCRM
Module      : Opportunities
Environment : Local EspoCRM

============================================================
1. OPPORTUNITIES MODULE ACCESS AND LIST
============================================================

FR-OPP-001 — Opportunities Module Access
The user should be able to access the Opportunities module.

FR-OPP-002 — Opportunities List View
The Opportunities module should provide a List view for displaying
Opportunity records.

FR-OPP-003 — Opportunities Empty State
When no Opportunity records are available, the Opportunities list
should display an appropriate "No Data" state.

FR-OPP-004 — Opportunity Page Counter
The Opportunities list should display the current page/record
counter. During exploratory observation, the empty list displayed
"0/0".

FR-OPP-005 — Pagination
The Opportunities List view should provide pagination controls.

FR-OPP-006 — Kanban View
The Opportunities module should provide a Kanban view.

FR-OPP-007 — Kanban Stage Columns
The Kanban view should provide stage-based columns for the observed
Opportunity stages:
- Prospecting
- Qualification
- Proposal
- Negotiation
- Closed Won

============================================================
2. CREATE OPPORTUNITY
============================================================

FR-OPP-008 — Create Opportunity
The user should be able to open the Create Opportunity form.

FR-OPP-009 — Save Opportunity
The Create Opportunity form should provide a Save action.

FR-OPP-010 — Cancel Opportunity Creation
The Create Opportunity form should provide a Cancel action.

FR-OPP-011 — Additional Save Actions
The Create Opportunity form should provide:
- Save & Continue Editing
- Save & New

These actions are available through the three-dot menu.

============================================================
3. OPPORTUNITY NAME
============================================================

FR-OPP-012 — Opportunity Name
The Create Opportunity form should provide a Name field.

FR-OPP-013 — Mandatory Opportunity Name
The Opportunity Name field should be mandatory and the system
should validate the field when the user attempts to save without
providing the required value.

============================================================
4. ACCOUNT
============================================================

FR-OPP-014 — Account Selection
The Opportunity should provide an Account field allowing an
existing Account to be selected.

FR-OPP-015 — Create Account

Account.

============================================================
12. OPPORTUNITY CREATION
============================================================

FR-OPP-037 — Create Opportunity with Valid Data
The user should be able to create an Opportunity by providing valid
mandatory information and saving the record.

FR-OPP-038 — Cancel Unsaved Opportunity
The user should be able to cancel Opportunity creation without
saving the new record.

FR-OPP-039 — Save & Continue Editing
The user should be able to save an Opportunity and remain on the
editing form.

FR-OPP-040 — Save & New
The user should be able to save an Opportunity and open a new
Create Opportunity form.

============================================================
EXPLORATORY OBSERVATIONS / DATA LIMITATIONS
============================================================

1. The Opportunities List displayed No Data during exploratory
   observation.

2. The Opportunities page displayed 0/0 while no records existed.

3. Teams selection displayed No Data in the current environment.

4. The observed Kanban view contained stage columns for:
   Prospecting, Qualification, Proposal, Negotiation and Closed Won.

5. Closed Lost was observed as a selectable Opportunity Stage in
   the Create Opportunity form, although a Closed Lost Kanban column
   was not observed in the documented Kanban view.

6. Account and Contact controls provided options to select existing
   records or create new records.

7. The Amount field was observed as mandatory and displayed USD.

8. Name and Close Date were observed as mandatory fields.

9. The actual validation messages and save behavior for mandatory
   fields must be confirmed during formal test execution.

10. The requirements in this v1.0 document are based on exploratory
    observation. Execution findings may require clarification in a
    later version (v1.1).
