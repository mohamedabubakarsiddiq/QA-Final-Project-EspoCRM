6. Key QA Observations

6.1 Account Name is the only mandatory field identified during testing.

6.2 Other Account fields tested were optional.

6.3 Phone numbers can be saved both with and without selecting a country code.

6.4 Duplicate detection displays the message:
"The record you are creating might already exist"

6.5 A duplicated Account can be saved successfully after changing Account data.

6.6 Locked Accounts cannot be edited.

6.7 Locked Accounts can be unlocked, after which editing becomes available again.

6.8 User Access displays Read, Edit, Delete and Stream access levels. No permission controls were available from the User Access screen during testing.

6.9 The Followers functionality successfully supports adding and removing users as followers.

6.10 Followed Accounts are correctly displayed through the Followed filter.

6.11 Starred Accounts are correctly displayed through the Starred filter.

6.12 Only My correctly displayed Accounts assigned to the current Admin user.

6.13 The Personal Data section displayed Email as the available personal data during testing.


7. Audit Log Observation

The Audit Log was available and recorded the Account Lock activity.

The Description update was not displayed because auditing was disabled for the Description field.

The Unlock activity was not observed in the Audit Log and requires further investigation before being classified as a defect.


8. Defect / Investigation Summary

Confirmed Failed Test Cases: 0

Confirmed Defects: 0

Investigation Item:

Audit Log – Unlock activity was not displayed while Lock activity was recorded.

The Unlock behavior should be verified against the expected EspoCRM audit behavior before raising a confirmed defect.
