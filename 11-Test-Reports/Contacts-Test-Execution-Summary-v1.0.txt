5. IMPORTANT EXECUTION OBSERVATIONS

5.1 Name Fields

Execution corrected the initial reconnaissance assumption regarding mandatory Name fields.

- Prefix is optional.
- First Name is optional.
- Last Name is mandatory.

When Last Name was left blank, the system displayed:
- "Not valid"
- "Last Name is required"

The Contact was prevented from being saved.

5.2 Email Validation

Valid email addresses were saved and displayed correctly.

Invalid email input was rejected with:
- "Not valid"
- "Email should be a valid email"

5.3 Email Controls

- Opt Out selection was retained and the opted-out email was displayed with strikethrough.
- Invalid status was retained and the email was displayed with strikethrough.
- Email removal worked successfully.
- Starred selection could be made, but the selected Starred state was not visibly retained after reopening. This resulted in BUG-CON-001.

5.4 Phone Validation

Mobile phone numbers were successfully saved both with and without a country code.

India (+91) country code was successfully supported.

Multiple phone numbers of different types were saved successfully.

An invalid/non-10-digit Office number was rejected with:
- "Not valid"
- "Phone is too long"

5.5 Account Relationship

Contacts could be associated with existing Accounts.

Multiple Accounts could be selected.

After selecting an Account, the additional Title field became available.

5.6 Personal Data

Personal Data displayed:
- Email
- Name
- Phone

Individual fields and Select All could be selected.

Erasure displayed:
"Checked fields will be erased permanently. Are you sure?"

After erasure:
- "Done" was displayed.
- The erased email displayed an ERASED identifier after reopening.

5.7 User Access

User Access displayed Admin with:
- Read — Selected
- Edit — Selected
- Delete — Selected
- Stream — Selected

Permissions could not be changed from the User Access page.

5.8 Search and Filters

Existing Contacts were searchable successfully.

A non-existing Contact search returned:
"No data"

The following filters were verified:
- All
- Starred
- Portal Users
- Only My
- Followed

The Portal Users filter returned no data because no Portal User data was available in the test environment.

Only My correctly displayed a Contact assigned to Admin.

Followed correctly displayed a followed Contact.

5.9 Followers

Admin could be added as a Contact follower.

The Contact appeared under the Followed filter.

Admin could be removed as a follower.

The Contact disappeared from the Followed filter after removal.

The Contacts module achieved a 97.73% pass rate with 43 of 44 test cases passing.

The module is functionally stable across the major areas tested. One medium-severity defect remains open regarding the visible persistence of the Starred Email state after reopening a Contact.

Recommended next action:
Retest BUG-CON-001 after the issue is fixed or configuration is changed, and verify that the selected Starred email remains visibly indicated after saving and reopening the Contact.
